13 steps — a school library's three linked tables, 80 rows in total, all loaded by importing, not typed by hand.

Miért importálunk, és nem gépelünk be mindent kézzel? A valóságban egy adatbázis majdnem sosem úgy épül fel, hogy valaki egyenként beírja az adatokat. Az adatok rendszerint már léteznek valahol — egy Excel-táblázatban, egy másik iskolai rendszer exportjában, egy nyilvános statisztikai adathalmazban — és ezeket CSV formátumban importáljuk az adatbázisba. A DB Browser felülete angol nyelvű, ezért minden feladatnál megadjuk az angol menüpontot is, és minden feladat végén egy rövid Miért? doboz elmagyarázza, mire jó az adott lépés.

Oszlopjelölések az import után elvárt szerkezetben: PK primer kulcs · AI automatikus számozás · NN kötelező mező · FK idegen kulcs (másik táblára mutat)

Zašto uvozimo, a ne upisujemo sve ručno? U stvarnom svetu baza podataka se skoro nikad ne pravi tako da neko ručno, jedan po jedan, upisuje podatke. Podaci obično već postoje negde — u Excel tabeli, u izvozu iz nekog drugog školskog sistema, u javnom statističkom skupu podataka — i njih uvozimo u bazu u CSV formatu. Interfejs DB Browser-a je na engleskom, zato svaki zadatak navodi i englesku stavku menija, a na kraju svakog zadatka kratak okvir Zašto? objašnjava čemu služi taj korak.

Oznake kolona u strukturi koju očekujemo nakon uvoza: PK primarni ključ · AI automatsko numerisanje · NN obavezno polje · FK strani ključ (veza sa drugom tabelom)

Why import instead of typing everything by hand? In the real world a database is almost never built by someone typing in data one row at a time. Data usually already exists somewhere — in a spreadsheet, in an export from another school system, in a public statistical dataset — and you import it into the database as CSV. DB Browser's interface is in English, so every task also gives the English menu path, and a short Why? box at the end of each task explains the point of that step.

Column markers in the structure expected after import: PK primary key · AI auto-increment · NN not null · FK foreign key (points to another table)

ELLENŐRZÉSEN: preview the CSV file

Mielőtt importálnál, nézd át a tanulok.csv előnézetét fent. Figyeld meg: az első sor a fejléc (oszlopnevek), utána vesszővel elválasztva jönnek az adatok.

💡 Miért? Importálás előtt mindig érdemes megnézni a forrásfájlt — ha rossz az elválasztó vagy hiányzik a fejléc, az import hibás lesz vagy értelmetlen oszlopneveket kapsz.
2
ÚJ ADATBÁZISEN: File → New Database

Hozz létre egy teljesen új, üres adatbázist konyvtar.db néven. Ebbe importáljuk majd mind a három táblát.

💡 Miért? Egy üres adatbázis a tiszta kiindulópont — nem kell kézzel megterveznünk a táblákat, mert az import automatikusan létrehozza őket a CSV szerkezete alapján.
3
IMPORTEN: File → Import → Table from CSV file...

Másold ki a tanulok.csv adatait a 📋 gombbal, illeszd be egy üres szöveges fájlba, mentsd el tanulok.csv néven, majd importáld. Az első sor legyen fejléc, az elválasztó vessző (,).

💡 Miért? Ez a valódi munkafolyamat: 25 sort begépelni percekig tartana és hibázni is könnyű lenne — az import másodpercek alatt, hiba nélkül tölti be ugyanazt.
4
IMPORTkonyvek.csv

Ugyanígy importáld a konyvek.csv adatait is, külön Konyvek táblába.

💡 Miért? Ugyanaz a technika, más adatforrás — ez mutatja, hogy az import folyamat bármilyen táblára megismételhető.
5
IMPORTkolcsonzesek.csv

Importáld a kolcsonzesek.csv adatait a Kolcsonzesek táblába. Figyelj: néhány sorban a visszahozva mező üres — ez szándékos, ezeket a könyveket még nem hozták vissza.

💡 Miért? Ez a tábla köti össze a másik kettőt (tanuló ↔ könyv) — enélkül nem derülne ki, ki mit kölcsönzött.
6
ELLENŐRZÉSEN: Database Structure / Browse Data

Nyisd meg a Database Structure fület: mind három tábla létrejött? A Browse Data fülön alul nézd meg a sorok számát — egyezik-e a forrással (25 / 25 / 30)?

💡 Miért? Egy hibás import gyakran néma — nem dob hibaüzenetet, csak kevesebb sor érkezik be. Mindig ellenőrizd a sorok számát import után.
7
SZŰRÉSEN: Browse Data · Tanulok

A Tanulok táblánál használd az osztaly oszlop feletti szűrőmezőt. Hány tanuló van a 8.a osztályban?

💡 Miért? A szűrés teszi lehetővé, hogy nagy adathalmazból gyorsan kiválogassuk a releváns sorokat — pontosan ezt fogja majd a SQL WHERE parancsa is csinálni.
8
RENDEZÉSEN: Browse Data · Konyvek

A Konyvek táblánál kattints a kiadas_eve oszlop fejére a rendezéshez. Melyik a legrégebbi és melyik a legújabb könyv a könyvtárban?

💡 Miért? A rendezés segít mintákat észrevenni anélkül, hogy végig kellene nézni mind a 25 sort egyenként.
9
SZŰRÉSEN: Browse Data · Kolcsonzesek

A Kolcsonzesek táblánál szűrj úgy, hogy a visszahozva mező üres legyen. Hány könyv van jelenleg kölcsönben, amit még nem hoztak vissza?

💡 Miért? Az üres mező felismerése és szűrése gyakori valós feladat — pontosan így derítené ki egy könyvtáros, kinél van még könyv.
10
KAPCSOLÁSEN: cross-reference two tables

Keresd meg, mely 8.a osztályos tanulóknak van jelenleg kint lévő (vissza nem hozott) könyve! Nézd meg a Tanulok táblában a 8.a-sok id-ját, majd keresd meg ezeket a Kolcsonzesek táblában, ahol üres a visszahozva.

💡 Miért? Ez a feladat gyakorolja, hogy a kapcsolódó táblák (tanulo_id) hogyan kötik össze az információt két tábla között — pontosan ez a gondolkodásmód kell majd a SQL JOIN-hoz.
11
JAVÍTÁSEN: Database Structure → Modify Table

Importálás után ellenőrizd az oszlopok típusát — a CSV import gyakran mindent TEXT-ként hoz be. Javítsd INTEGER-re az evfolyam, kiadas_eve, tanulo_id és konyv_id oszlopokat.

💡 Miért? A helyes típus fontos: szövegként a "9" nagyobbnak tűnhet, mint "10" (mert karakterenként hasonlítja össze), számként viszont helyesen rendeződik.
12
EXPORTEN: File → Export → Table(s) as CSV file...

Exportáld vissza a Konyvek táblát CSV fájlba. Nyisd meg az exportált fájlt, és ellenőrizd, hogy minden sor benne van.

💡 Miért? Az adatbázis nemcsak befogad, hanem ki is tud adni adatot — ez zárja a kört: import → munka az adatbázisban → export, például ha valakinek Excelben kell továbbküldeni az eredményt.
13
MENTÉSEN: Write Changes

Kattints a Write Changes gombra, zárd be a programot, majd nyisd meg újra a konyvtar.db fájlt. Ellenőrizd, hogy mindhárom tábla és minden sor megmaradt.

💡 Miért? A Write Changes nélkül minden módosítás elvész, amint bezárod a programot — ez legyen minden munka utolsó lépése.

Készen vagy, ha:

1
PREGLEDEN: preview the CSV file

Pre uvoza, pogledaj pregled tanulok.csv iznad. Primeti: prvi red je zaglavlje (nazivi kolona), a zatim slede podaci odvojeni zarezom.

💡 Zašto? Pre uvoza je uvek dobro pogledati izvornu datoteku — ako je separator pogrešan ili nedostaje zaglavlje, uvoz će biti neispravan ili ćeš dobiti besmislene nazive kolona.
2
NOVA BAZAEN: File → New Database

Napravi potpuno novu, praznu bazu podataka pod nazivom konyvtar.db. U nju ćemo uvesti sve tri tabele.

💡 Zašto? Prazna baza je čista polazna tačka — ne moramo ručno da projektujemo tabele, jer ih uvoz automatski pravi na osnovu strukture CSV-a.
3
UVOZEN: File → Import → Table from CSV file...

Kopiraj podatke iz tanulok.csv dugmetom 📋, nalepi ih u praznu tekstualnu datoteku, sačuvaj kao tanulok.csv, pa uvezi. Prvi red neka bude zaglavlje, separator zarez (,).

💡 Zašto? Ovo je pravi tok rada: ručno upisivanje 25 redova bi trajalo i lako bi doveli do greške — uvoz isto to učita za nekoliko sekundi, bez greške.
4
UVOZkonyvek.csv

Na isti način uvezi i podatke iz konyvek.csv, u posebnu tabelu Konyvek.

💡 Zašto? Ista tehnika, drugi izvor podataka — ovo pokazuje da se postupak uvoza može ponoviti za bilo koju tabelu.
5
UVOZkolcsonzesek.csv

Uvezi podatke iz kolcsonzesek.csv u tabelu Kolcsonzesek. Pažnja: u nekim redovima je polje visszahozva prazno — to je namerno, te knjige još nisu vraćene.

💡 Zašto? Ova tabela povezuje druge dve (učenik ↔ knjiga) — bez nje ne bismo znali ko je šta pozajmio.
6
PROVERAEN: Database Structure / Browse Data

Otvori karticu Database Structure: da li su sve tri tabele nastale? Na kartici Browse Data pogledaj broj redova — poklapa li se sa izvorom (25 / 25 / 30)?

💡 Zašto? Neuspešan uvoz je često "tih" — ne prijavljuje grešku, samo stigne manje redova. Uvek proveri broj redova nakon uvoza.
7
FILTRIRANJEEN: Browse Data · Tanulok

Kod tabele Tanulok koristi polje za filter iznad kolone osztaly. Koliko učenika je u odeljenju 8.a?

💡 Zašto? Filtriranje omogućava da iz velikog skupa podataka brzo izdvojimo relevantne redove — baš to će raditi i WHERE naredba u SQL-u.
8
SORTIRANJEEN: Browse Data · Konyvek

Kod tabele Konyvek klikni na zaglavlje kolone kiadas_eve da sortiraš. Koja je najstarija, a koja najnovija knjiga u biblioteci?

💡 Zašto? Sortiranje pomaže da uočiš obrasce bez potrebe da ručno pregledaš svih 25 redova.
9
FILTRIRANJEEN: Browse Data · Kolcsonzesek

Kod tabele Kolcsonzesek filtriraj tako da polje visszahozva bude prazno. Koliko knjiga je trenutno pozajmljeno, a nije vraćeno?

💡 Zašto? Prepoznavanje i filtriranje praznog polja je čest, stvaran zadatak — baš tako bi bibliotekar otkrio kod koga je još knjiga.
10
POVEZIVANJEEN: cross-reference two tables

Pronađi koji učenici iz odeljenja 8.a trenutno imaju pozajmljenu (nevraćenu) knjigu! Pogledaj id učenika iz 8.a u tabeli Tanulok, pa potraži te identifikatore u tabeli Kolcsonzesek, tamo gde je visszahozva prazno.

💡 Zašto? Ovaj zadatak vežba kako povezane tabele (tanulo_id) spajaju informacije iz dve tabele — baš taj način razmišljanja će ti trebati za SQL JOIN.
11
ISPRAVKAEN: Database Structure → Modify Table

Nakon uvoza, provери tip kolona — uvoz iz CSV-a često sve uveze kao TEXT. Promeni u INTEGER kolone evfolyam, kiadas_eve, tanulo_id i konyv_id.

💡 Zašto? Tačan tip je važan: kao tekst, "9" može izgledati veće od "10" (jer se poredi karakter po karakter), a kao broj se ispravno sortira.
12
IZVOZEN: File → Export → Table(s) as CSV file...

Izvezi tabelu Konyvek nazad u CSV datoteku. Otvori izvezenu datoteku i proveri da li su svi redovi tu.

💡 Zašto? Baza podataka ne samo da prima, nego i izdaje podatke — ovo zatvara krug: uvoz → rad u bazi → izvoz, na primer kada rezultat treba poslati dalje u Excelu.
13
ČUVANJEEN: Write Changes

Klikni Write Changes, zatvori program, pa ponovo otvori konyvtar.db. Proveri da li su sve tri tabele i svi redovi ostali sačuvani.

💡 Zašto? Bez Write Changes svaka izmena se gubi čim zatvoriš program — ovo mora biti poslednji korak svakog rada.

Gotov si kada:

1
CHECKpreview the CSV file

Before importing, look at the tanulok.csv preview above. Notice: the first row is the header (column names), followed by comma-separated data.

💡 Why? Always check a source file before importing — a wrong delimiter or a missing header will break the import or give you meaningless column names.
2
NEW DATABASEFile → New Database

Create a brand-new, empty database named konyvtar.db. We will import all three tables into it.

💡 Why? An empty database is a clean starting point — we don't need to design the tables by hand, because the import wizard creates them automatically from the CSV structure.
3
IMPORTFile → Import → Table from CSV file...

Copy the tanulok.csv data with the 📋 button, paste it into an empty text file, save it as tanulok.csv, then import it. The first row should be the header, the delimiter a comma (,).

💡 Why? This is the real workflow: typing 25 rows by hand would take minutes and invite mistakes — importing loads the same data in seconds, error-free.
4
IMPORTkonyvek.csv

Import the konyvek.csv data the same way, into a separate Konyvek table.

CONNECTcross-reference two tables

Find which 8.a students currently have a book out (not yet returned). First look up the ids of the 8.a students in the Tanulok table, then search for those ids in the Kolcsonzesek table where visszahozva is empty.

💡 Why? This task practices how linked tables (tanulo_id) connect information across two tables — this exact thinking is what you'll need for a SQL JOIN.

FIXDatabase Structure → Modify Table

After importing, check the column types — CSV import often brings everything in as TEXT. Change evfolyam, kiadas_eve, tanulo_id and konyv_id to INTEGER.

💡 Why? The correct type matters: as text, "9" can look bigger than "10" (compared character by character), but as a number it sorts correctly.

EXPORTFile → Export → Table(s) as CSV file...

Export the Konyvek table back to a CSV file. Open the exported file and check that every row is there.

💡 Why? A database doesn't just take in data, it can give it back out too — this closes the loop: import → work in the database → export, for example when the result needs to be sent on in Excel.
13
SAVEWrite Changes

Click Write Changes, close the program, then reopen konyvtar.db. Check that all three tables and every row are still there.

💡 Why? Without Write Changes, every change is lost as soon as you close the program — this should be the last step of every session.
